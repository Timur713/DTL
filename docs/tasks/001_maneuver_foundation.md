# Задача 001: модель манёвра и проверяемый пример разрешения конфликта

Исполнитель: GPT-6.1-Sol, reasoning **xhigh**. Координатор отвечает за общий контракт, интеграцию и независимую проверку. Область этапа — кинематика и проверка одного примера; общий планировщик для всей группы пока не нужен.

## Контекст и исходное состояние

Прочитать `AGENTS.md`, `README.md`, `rules.json`, `docs/model.md`, `docs/contracts.md`, `docs/target-zone-decision.md`, текущий анализатор и тесты. Основной режим — `metric / nominal / base`, H=9260 м, V=300 м, T=1200 с. `bounded_stress` уже реализован для baseline; перенос его на управляемые траектории не входит в этот этап.

**Цель теперь окружена сферой, а не цилиндром.** F020 на 8100 м не нарушает сферу радиусом 5000 м с центром на высоте 0. Первое событие основного режима — F020/F038, примерно `(280.313481630, 311.964821195)` с. Всего baseline имеет 12 событий: 3 пары, 5 с дроном, 4 с целью. Никаких исходных nominal-нарушений. Эти числа — контроль, не критерий подгонки.

Позиции и скорости всех исходных объектов сохраняются. Отдельная экспериментальная траектория может заменить F020 или F038 только в отдельном расчёте. Остальные 39 самолётов и дрон продолжают исходное движение. Цель — статическая сфера. Все лимиты движения читаются из `rules.json`; действуют границы высот сценария. У исходной траектории есть условный пункт назначения — исходная позиция на t=1200; пример должен вернуться к исходному конечному состоянию, а не просто улететь из сценария.

## Результат

1. **Отдельная модель кусочно заданной траектории.** Поддержать прямолинейный участок, плавное изменение скорости, согласованный поворот с ограничением крена и вертикальный манёвр с ограничениями vz/az. Положение и скорость непрерывны на стыках. Допустим небольшой честно описанный набор примитивов: например, тангенциальное ускорение только на прямой и поворот только при постоянной горизонтальной скорости. Одновременный разгон в повороте не обязателен. Не нужна 6DOF-модель. Отсутствие лимита скорости перекладки крена/рывка нужно указать как допущение.
2. **Независимая непрерывная проверка новой траектории.** Проверить разделение с каждым из остальных самолётов, обе сферы, высоту и ограничения движения на всём горизонте. Использовать точные формулы там, где они применимы. Для кривых допустима адаптивная проверка с обоснованными границами на всём интервале и явным `unresolved`, когда точности недостаточно. Простое сгущение выборки не является непрерывной проверкой. Опишите численные гарантии честно: обычная floating-point арифметика не равна формальной верификации.
3. **Воспроизводимый пример на F020/F038.** Найти простой манёвр одного участника, устраняющий это событие при прежних порогах. Проверить его взаимодействия со всеми самолётами, дроном и целью, а также возврат к исходным положению/скорости на t=1200. Практичный первый кандидат — набор высоты, выдерживание, возврат при прежней горизонтальной скорости и курсе. Ровно 300 м допустимо по модели, но решение без запаса нужно явно отметить; не менять ради него правила. Допустимый пример не обязан быть оптимальным.
4. **Отчёт о проверке.** Показать baseline и кандидат: затронутые конфликты, новые нарушения/неопределённые интервалы, максимальное отклонение, длительность манёвра, предельные параметры движения, невязку конечного состояния. Остальные baseline-конфликты остаются отдельно: устранение одной пары не делает весь сценарий безопасным. Если кандидат не найден, зафиксировать проверенные варианты и ограниченный вывод, не объявлять невозможность всех манёвров.
5. **CLI и артефакты.** Отдельный CLI из любого cwd, детерминированные JSON и краткий Markdown-отчёт; CSV отсчётов для будущей визуализации. Сегменты/формулы — авторитетное описание траектории, CSV — только представление. Сохранять входные хеши, профиль и допущения. Проверять неподдерживаемые режимы и неверные данные. Baseline-отчёты и HTML не заменять экспериментом.
6. **Содержательные тесты.** Известные решения для прямой/ускорения/дуги/вертикального движения; непрерывность на стыках; нарушения между отсчётами; касания, равенство, начало/конец; лимиты внутри сегмента; плохие/nonfinite/bool-входы; проверка отсутствия ложной гарантии при `unresolved`; возврат к конечному состоянию; повторяемость CLI и пример на реальных данных.

Перед реализацией прислать координатору краткий контракт: примитивы, формулы, семантика safe/violation/unresolved, способ ограничения ошибки на интервале, структура результата. Существенные изменения общей модели согласует координатор. Не менять baseline-формат 1.1 и `rules.json` в рамках этой задачи; у нового модуля свой явно описанный контракт.

## Критерии готовности

- Примитивы имеют понятный контракт и математическую проверку; мгновенные скачки скорости не маскируются.
- Проверка не объявляет безопасным интервал только потому, что в отсчётах не найден конфликт. Равенство безопасно без подмены порогов допуском.
- Реальный пример воспроизводим и проверен относительно всех объектов, включая весь временной горизонт и конечное состояние.
- Ограничения поддержки и неопределённые случаи видны в отчёте; stress не применяется молча.
- Новые тесты и все 43 baseline-теста проходят; исходные файлы и baseline-артефакты не изменены.
- Координатор получил список файлов, команды, результаты, оставшиеся ограничения и вопросы для проверки.
